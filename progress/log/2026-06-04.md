## Sesión 2026-06-04 (noche) — token ML centralizado en Worker

**Contexto:** Dos usuarios (dueño + esposa) quieren publicar en la misma cuenta ML. El token en localStorage por dispositivo causaba conflictos en el refresh.

### Arquitectura implementada
Worker `mlpu-proxy.aronricocl.workers.dev` centraliza auth:
- KV `ML_TOKENS` (id `1f6324c3659d4388bec284825c2864be`) guarda `{ access_token, refresh_token, obtained_at, expires_in }`
- `POST /ml/auth/init`: recibe code OAuth, exchange con secrets del Worker, guarda en KV
- `GET /ml/auth/status`: responde `{ active, secs_left }` sin exponer token
- Proxy `/ml/*`: inyecta Authorization desde KV, renueva proactivo si <5min, reintenta en 401

### App.jsx
- Eliminados: estados `token`, `refreshToken`, funciones `refreshAccessToken`/`exchangeCode`, `setInterval` auto-refresh, input Client Secret
- Nuevo: `fetchAuthStatus` (poll 60s), `initAuth` (manda code a Worker)
- ONBOARDING: muestra `sessionActive` desde Worker
- `publish()` y `publishBatch()` ya no mandan Authorization header

### Infraestructura
- `wrangler kv namespace create ML_TOKENS` → id `1f6324c3659d4388bec284825c2864be`
- `wrangler secret put ML_CLIENT_ID` (3829359465845583)
- `wrangler secret put ML_CLIENT_SECRET`
- `wrangler deploy` → commit `30dc51c`

### Fix post-deploy (commit `2bc1e7a`)
